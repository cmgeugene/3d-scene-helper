# I2V 3D Scene Helper 제품 브리프

상태: 현재 제품 목적과 사용자 흐름을 설명하는 제품 브리프
관련 문서: [현재 기능과 실행법](../README.md) · [구현 로드맵](roadmap.md) · [AI Scene Assistant 설계](ai-scene-assistant.md) · [초기 아키텍처](architecture.md)

## 1. 제품 정의

I2V 3D Scene Helper는 비전문가가 브라우저에서 간단한 3D 오브젝트, 마네킹과 리깅 캐릭터, 카메라와 조명을 배치해 I2V 시작 프레임의 구도와 촬영 의도를 결정하는 로컬 우선 씬 디렉팅 도구다. 사용자는 정확한 크기의 PNG를 직접 내보낼 수 있고, Local Companion과 대화하며 장면 의미와 레퍼런스 역할을 정리한 뒤 현재 3D 레이아웃을 공간 기준으로 이미지 생성과 보정까지 이어갈 수 있다.

완전한 3D 모델러나 범용 이미지 편집기가 아니라 **카메라·블로킹·포즈·깊이 관계를 빠르게 고정하고, 그 의도를 이미지 생성 모델에 일관되게 전달하는 도구**다.

## 2. 주요 사용자 페르소나

**I2V 창작자 지민**

- 이미지-투-비디오 작업 전에 인물과 소품의 위치, 렌즈 느낌, 조명 방향을 확인해야 한다.
- Blender 수준의 모델링, 리깅, 재질 편집, 타임라인 학습은 원하지 않는다.
- 세로형·가로형 프레임을 빠르게 비교하고 생성 모델에 전달할 구조적으로 명확한 시작 프레임이 필요하다.
- 캐릭터 시트와 배경·스타일 레퍼런스를 쓰되, 레퍼런스가 3D에서 정한 카메라와 배치를 바꾸는 것은 원하지 않는다.
- 생성 결과를 보며 외형만 보정하거나 과거 3D 구도를 다시 불러와 별도 버전으로 발전시키고 싶다.
- 성공 기준은 “멋진 3D 작품”이 아니라 “촬영 의도가 분명하고 재현 가능한 키프레임을 짧은 시간 안에 얻는 것”이다.

## 3. 3분 골든패스

목표: 처음 방문한 사용자가 기본 장면에서 시작해 **3분 이내**에 `1080×1920` 깨끗한 PNG를 내려받는다. 이 흐름은 AI 연결 없이도 완결되는 제품의 기본 경로다.

| 누적 목표 시간 | 사용자 행동 | 확인 가능한 결과 |
|---|---|---|
| 0:00–0:15 | 앱을 연다. | 실제 바닥, 1.7m 마네킹, 중립 배경·스튜디오 조명, 눈높이 50mm 카메라가 있는 기본 장면이 보인다. |
| 0:15–0:30 | 화면비에서 `9:16`을 고른다. | 전체 3D 뷰포트 위에 세로 출력 프레임이 나타나고 프레임 바깥 장면은 반투명 매트로 어두워진다. |
| 0:30–1:00 | `큐브`를 추가하고 선택해 이동·회전·크기를 조정한다. | 아웃라이너, 기즈모, 속성 패널이 같은 선택과 변형을 표시한다. |
| 1:00–1:20 | 렌즈 `35mm`와 `전신` 샷 프리셋을 고른다. | 선택 피사체 경계를 기준으로 세로 프레임이 다시 잡힌다. |
| 1:20–1:40 | 조명 `시네마틱 역광`을 고른다. | 마네킹과 큐브가 읽히면서 역광 분위기가 적용된다. |
| 1:40–2:00 | `3분할선`과 `액션 안전 영역`을 켜고 구도를 미세 조정한다. | 가이드는 편집 프리뷰에만 보인다. |
| 2:00–2:15 | 장면을 로컬 저장하고 다시 연다. | 저장한 오브젝트·카메라·조명·출력 설정이 복원된다. |
| 2:15–2:45 | `PNG 내보내기`에서 `1080×1920`, `깨끗한 프레임`을 선택해 내보낸다. | 정확히 1080×1920인 PNG가 다운로드되고 바닥은 보이지만 그리드·축·선택선·기즈모·구도 가이드는 없다. |

### 3.1 대화형 키프레임 확장 흐름

기본 3D 구도가 준비된 사용자는 다음 흐름으로 이미지 생성과 보정까지 이어간다.

1. 프로젝트 Companion을 연결하고 장면의 실제 의미나 확인할 공간 관계를 Scene Assistant와 대화한다.
2. 앱은 현재 OutputCamera 렌더와 카메라에서 파생한 구조화된 레이아웃 정보를 대화에 함께 제공한다.
3. 사용자는 Layout, Background, Character, Style 레퍼런스를 프로젝트에 가져와 역할과 연결 대상을 지정한다.
4. 생성 전 검사에서 레이아웃·장면·레퍼런스의 무결성과 충돌을 확인한다.
5. 이미지 생성에서는 현재 3D 레이아웃이 카메라·크롭·배치·크기·포즈·깊이·가림의 최상위 기준이 된다.
6. 생성 결과와 당시 장면·레이아웃·레퍼런스·prompt 근거를 이력에서 확인한다.
7. 결과의 외형만 다듬을 때는 원본 키프레임을 사용해 보정하고, 구도를 바꿀 때는 저장된 3D 스냅샷을 현재 씬으로 불러와 새 분기를 만든다.

## 4. 기본 장면 계약

빈 공간 대신 다음이 항상 준비된 **기본 장면(starter scene)** 으로 시작한다.

- 월드 단위: `1 Three.js unit = 1m`.
- 레이어 0의 실제 출력 바닥. 편집 그리드·축은 바닥을 대신할 수 없다.
- 기준 키가 정확히 `1.7m`인 프리미티브 마네킹.
- 중립 배경과 `중립 스튜디오` 조명.
- 눈높이 `50mm` OutputCamera. `filmGauge`는 `36mm`로 고정한다.
- 새 장면과 `기본 장면으로 초기화`는 모두 이 구성을 재생성한다.

## 5. 기본 3D 편집 조작 계약

### 5.1 상단 도구막대

- `새 장면`, `기본 장면으로 초기화`
- `실행 취소`, `다시 실행`
- 화면비 선택: `16:9`, `9:16`, `1:1`, `2.39:1`
- 가이드 개별 토글과 `모든 가이드 숨기기`
- `로컬 저장`, `최근 장면 열기`, `JSON 가져오기`, `JSON 내보내기`
- `PNG 내보내기`

### 5.2 오브젝트와 변형

- 추가: `큐브`, `구`, `원기둥`, `평면`, `라운드 큐브`, `곡면`, `정삼각형`, `마네킹`, `방 세트`, 번들 리깅 캐릭터.
- Companion 연결 시 스킨된 GLB 2.0 캐릭터를 프로젝트에 가져올 수 있다. 가져온 캐릭터는 높이, 포함된 애니메이션의 시간과 미리보기, 매핑 가능한 양손·양발 IK를 제공한다.
- 선택: 뷰포트 메시 또는 아웃라이너 행. 빈 공간 클릭과 `Esc`로 선택 해제.
- 변형: `이동`, `회전`, `크기`; 기즈모와 숫자 입력을 모두 제공한다.
- 속성: 이름, 색상, 표시/숨김.
- 작업: 복제, 삭제.
- 단축키: `W` 이동, `E` 회전, `R` 크기, `Delete/Backspace` 삭제, `Cmd/Ctrl+D` 복제, `Esc` 선택 해제, `Cmd/Ctrl+Z` 실행 취소, `Cmd/Ctrl+Shift+Z` 다시 실행.
- 텍스트 입력 요소에 포커스가 있으면 장면 단축키를 실행하지 않는다.
- 연속 기즈모 드래그는 문서와 히스토리에 한 번만 확정한다.

### 5.3 카메라와 구도

- 렌즈 프리셋: `18mm`, `24mm`, `35mm`, `50mm`, `85mm`.
- 샷 프리셋: `눈높이 미디엄`, `전신`, `로우 앵글`, `하이 앵글`, `클로즈업`, `더치 앵글`.
- 선택 기반 작업: `선택 항목 프레임에 맞추기`, `선택 항목 바라보기`. 선택이 없으면 카메라를 바꾸지 않고 상태 메시지를 알린다.
- 샷 거리는 임의의 좌표가 아니라 피사체 경계 또는 1.7m 기준 키에서 계산한다.
- 구도 가이드: `3분할선`, `중앙 십자선`, `액션 안전 영역 5%`, `타이틀 안전 영역 10%`.
- 전체 뷰포트에서 출력 프레임 바깥 장면도 편집할 수 있으며, 바깥 영역은 반투명 매트로 구분한다.
- 출력 프레임 안쪽은 PNG와 정확히 같은 구도다. 브라우저 크기나 기기 픽셀 비율은 출력 구도를 바꾸지 않는다.

### 5.4 조명과 배경

- 조명 프리셋: `중립 스튜디오`, `주광`, `일몰`, `야간`, `시네마틱 역광`.
- 조정: 노출, 배경색, 키 라이트 방향, 그림자 켜기/끄기.
- `프리셋으로 재설정`은 조명·배경만 되돌리고 카메라와 오브젝트는 바꾸지 않는다.
- 기본 조명은 환경광과 키/필/림 구성으로 제한하며, 그림자를 만드는 라이트는 최대 하나다.

### 5.5 움직임 구도 가이드

- 선택한 오브젝트 하나에 피사체 이동 방향 가이드 하나를 둘 수 있다.
- 장면에 카메라 이동 방향 가이드 하나를 둘 수 있다.
- 방향 프리셋: 피사체 `왼쪽/오른쪽/위/아래/앞/뒤`, 카메라 `팬/틸트/돌리/오빗`.
- 방향 가이드는 이후 움직임을 고려해 앵커샷의 여백과 깊이를 잡기 위한 구도 보조 기능이다.
- 모호한 강도 입력과 별도 장면 메모는 편집 UI에 제공하지 않는다. AI API 호출도 하지 않는다.

### 5.6 저장과 복원

- 마지막 유효 장면을 브라우저 로컬 저장소에 저장하고 새로고침 후 복원한다.
- 장면 JSON을 파일로 내보내고 가져올 수 있다.
- 가져오기는 전체 문서를 검증한 뒤에만 현재 장면과 자동 저장을 교체한다. 손상되었거나 지원하지 않는 버전이면 둘 다 보존하고 한국어 오류를 표시한다.

## 6. 화면비와 출력 크기

| 화면비 | 고정 출력 프리셋 | 비고 |
|---|---|---|
| `16:9` | `1280×720`, `1920×1080` | HD, Full HD |
| `9:16` | `1080×1920` | 세로 Full HD |
| `1:1` | `1080×1080` | 정사각형 |
| `2.39:1` | `1920×804` | 정수 픽셀 반올림으로 실제 비율은 약 2.388:1. 늘이기 없이 같은 카메라 프레임을 렌더링한다. |

사용자 지정 출력은 다음 규칙을 모두 만족해야 한다.

- 너비와 높이는 각각 `64..4096px`의 정수다.
- 활성 화면비에 잠긴다. 너비를 바꾸면 높이를, 높이를 바꾸면 너비를 다시 계산한다.
- 반올림 때문에 활성 비율과 정확히 일치하지 않는 정수 크기는 허용 가능한 가장 가까운 값으로 표시한다.
- 임의의 비율 불일치를 묵인해 이미지를 늘이거나 찌그러뜨리지 않고 입력을 거부한다.
- 모든 출력은 `pixelRatio=1`인 정확한 픽셀 크기로 생성한다.

### 출력 모드

- `깨끗한 프레임`(기본): 장면 콘텐츠 레이어 0만 출력한다.
- `참조 포함`: 레이어 0과 참조 주석 레이어 2, 선택한 퍼센트 기반 구도 가이드를 합성한다.
- 두 모드 모두 편집 전용 레이어 1의 그리드, 축, 선택선, 기즈모를 절대 포함하지 않는다.

## 7. 데스크톱 텍스트 와이어프레임

지원 기준은 데스크톱 브라우저 `1280×720` 이상이다. 더 좁으면 편집기를 억지로 축소하지 않고 `이 편집기는 1280×720 이상의 데스크톱 화면이 필요합니다.`를 표시한다.

```text
┌────────────────────────────────────────────────────────────────────────────────────────────┐
│ I2V 3D Scene Helper │ 새 장면 │ 초기화 │ 실행 취소/다시 실행 │ 화면비 9:16 │ 저장 │ PNG 내보내기 │
├──────────────────────┬──────────────────────────────────────────────┬──────────────────────┤
│ 오브젝트 추가         │                                              │ 속성                  │
│ [큐브] [구]           │          레터박스 바깥 마스크               │ 이름 [마네킹        ] │
│ [원기둥] [평면]       │      ┌──────── 출력 프레임 ────────┐         │ 변형 [이동/회전/크기] │
│ [마네킹]              │      │ 실제 장면 + 실제 바닥        │         │ 위치/회전/크기 숫자값 │
│                      │      │ 3분할·안전영역 DOM 가이드    │         │ 색상 / 표시           │
│ 장면 목록             │      │ 선택선·기즈모는 편집 전용    │         │ 복제 / 삭제           │
│ ▾ 장면                │      └──────────────────────────────┘         │                      │
│   바닥                │                                              │ 카메라                │
│   마네킹 ●            │          궤도/팬 편집 내비게이션             │ 렌즈 [35mm] / 샷      │
│   큐브                │                                              │ 프레임/바라보기       │
│                      │                                              │ 조명 / 배경 / 가이드  │
├──────────────────────┴──────────────────────────────────────────────┴──────────────────────┤
│ 상태: 마네킹 선택됨 · 이동 모드 · 로컬 저장 완료                                      │
└────────────────────────────────────────────────────────────────────────────────────────────┘
```

- 왼쪽: 오브젝트 추가와 아웃라이너.
- 가운데: 출력 화면비를 유지한 레터박스 프리뷰와 편집 내비게이션.
- 오른쪽: 선택 오브젝트, 카메라, 조명, 가이드의 문맥별 속성.
- 아래: 선택, 모드, 저장, 카메라 무동작, 오류를 알리는 `aria-live` 상태 표시줄.

## 8. 출력 대화상자 텍스트 와이어프레임

```text
┌────────────── PNG 내보내기 ──────────────┐
│ 파일 이름                                │
│ [i2v-start-frame____________________] .png│
│                                          │
│ 화면비        [9:16                 ▾]   │
│ 해상도        [1080×1920            ▾]   │
│ 사용자 지정   너비 [1080] 높이 [1920] 🔒 │
│                                          │
│ 출력 내용                                │
│ (●) 깨끗한 프레임                        │
│ ( ) 참조 포함                            │
│                                          │
│ 결과: 1080×1920 PNG · sRGB               │
│ [취소]                 [PNG 내보내기]     │
└──────────────────────────────────────────┘
```

- 진행 중: `PNG를 만드는 중입니다…`를 표시하고 중복 실행을 막는다.
- 실패: `PNG를 만들지 못했습니다. 장면은 그대로 보존되었습니다.`와 원인별 재시도 안내를 표시한다.
- 파일 이름은 파일 시스템에 안전한 값으로 정리한다.
- `Esc`와 `취소`는 출력 없이 닫고, 모달 안에서 포커스를 가둔 뒤 닫을 때 원래 버튼으로 되돌린다.

## 9. Scene Assistant와 레퍼런스 제품 원칙

- 현재 OutputCamera 레이아웃은 fresh/edit 모두 카메라, 크롭, 배치, 크기, 포즈, 방향, 깊이와 가림의 최상위 공간 기준이다.
- 기존 생성 결과는 외형·정체성·의상·재질·색감의 기준이 될 수 있지만 현재 3D 레이아웃의 공간 구성을 덮어쓰지 않는다.
- 레퍼런스는 역할과 연결 대상을 가진 프로젝트 자산으로 저장하며 생성 포함 여부, 사용 범위와 제외 범위를 사용자가 제어한다.
- Scene Assistant는 일반 대화에서도 현재 레이아웃과 화면상 방향을 근거로 답하고, 이미지 번호보다 안정적인 레퍼런스 이름·역할·ID를 사용한다.
- 생성 결과는 원본 이미지뿐 아니라 당시 장면, 레이아웃, 레퍼런스, 첨부 순서와 prompt 근거를 추적할 수 있어야 한다.
- 대화 기록 자체를 프로젝트의 영구 원본으로 간주하지 않는다. 장면 데이터, 의미·연출 데이터와 Companion 문맥의 장기 책임 경계는 실제 사용 결과를 바탕으로 계속 다듬는다.

## 10. 언어 정책

UI 문구, 오류, 상태 메시지와 도움말은 한국어 우선이다. 현재 i18n 프레임워크, 언어 선택기와 번역 리소스 계층은 두지 않는다. 코드 식별자와 JSON 필드명은 안정성을 위해 영어를 사용한다.

## 11. 현재 제품 품질 기준

- 3D 편집과 PNG/JSON 내보내기는 Companion이나 외부 생성 서비스가 없어도 동작한다.
- OutputCamera가 뷰포트 출력 프레임, clean/reference PNG와 이미지 생성 레이아웃의 구도 기준이다.
- 손상되거나 지원하지 않는 파일과 서버 응답은 현재 장면과 기존 프로젝트 자산을 변경하지 않고 거부한다.
- 새 장면, 저장·복원, generation 스냅샷 적용과 보정 분기는 사용자가 현재 작업을 잃지 않도록 명시적인 경계를 가진다.
- 이미지 생성의 실제 첨부 순서와 역할, 입력 스냅샷과 해시를 이력에서 재검증할 수 있다.
- WebGL이 없거나 context를 잃어도 직렬화된 장면은 보존한다.
- unit, typecheck, lint, production build와 실제 Chromium/WebGL 검증의 책임을 구분한다.

## 12. 현재 지원하지 않는 범위

- 계정, 클라우드 장면 저장과 실시간 협업.
- 외부 사용자용 installer, 코드 서명, 자동 업데이트가 있는 독립 실행형 데스크톱 배포.
- 메시 모델링, 스컬프팅, UV·재질·텍스처 편집과 범용 에셋 저작.
- 일반 목적의 임의 메시 import와 에셋 마켓플레이스. 현재 3D import는 스킨된 캐릭터 GLB에 한정한다.
- 다중 애니메이션 클립 편집, 키프레임 timeline, physics, particle과 고급 후처리.
- 곡면·재귀·거울 속 거울 반사.
- cloud 이미지 생성 공급자 계정 관리와 원격 Codex App Server 운영.
- 모바일 touch 편집과 다국어화 프레임워크.
