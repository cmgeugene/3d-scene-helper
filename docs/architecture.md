# I2V 3D Scene Helper 아키텍처

상태: Session S00에서 고정한 MVP 기술 계약
관련 문서: [제품 브리프](product-brief.md) · [구현 계획](../.hermes/plans/2026-07-30_095647-i2v-3d-scene-helper-session-plan.md)

## 1. 시스템 범위

MVP는 React, TypeScript, Vite, React Three Fiber와 Three.js로 만드는 **브라우저 전용 단일 페이지 애플리케이션**이다. Zustand가 상태를 관리하고 Zod가 저장 문서 경계를 검증한다. 서버, 계정, 원격 데이터베이스는 없으며 장면은 브라우저 저장소와 사용자가 내려받는 JSON/PNG 안에만 존재한다.

핵심 원칙은 다음과 같다.

1. 직렬화 가능한 장면 문서만 영속적인 진실의 원천으로 삼는다.
2. 편집 중 UI 상태와 Three.js 런타임 객체를 문서 밖에 둔다.
3. 문서 소유 OutputCamera 하나가 레터박스 프리뷰와 PNG 구도를 모두 결정한다.
4. PNG는 편집 화면 캡처가 아니라 정확한 크기의 오프스크린 렌더로 만든다.
5. 실제 브라우저 WebGL 동작은 실제 브라우저에서 검증한다.

## 2. 고정 좌표계와 기본 장면

- `1 Three.js unit = 1m`다. 위치와 크기는 미터 단위의 평범한 숫자로 저장한다.
- 프리미티브 마네킹의 기준 키는 정확히 `1.7m`다.
- 카메라 샷 계산은 피사체 경계 또는 1.7m 기준 키를 사용한다. 설명되지 않은 카메라 위치 상수를 프리셋 계약으로 삼지 않는다.
- 기본 장면은 레이어 0의 **실제 출력 바닥**, 1.7m 마네킹, 중립 배경, 중립 스튜디오 조명, 눈높이 50mm OutputCamera를 포함한다.
- 그리드와 축은 편집 도우미일 뿐이며 실제 바닥을 대신하지 않는다. 따라서 기본 깨끗한 PNG에는 바닥이 보이고 그리드와 축은 보이지 않는다.

## 3. 상태 경계

### 3.1 직렬화 문서: `SceneDocument`

버전이 있는 Zod 스키마와 그 스키마에서 추론한 TypeScript 타입이 유일한 문서 계약이다. 문서는 JSON으로 안전하게 표현되는 원시값, 배열, 평범한 객체만 가진다.

문서가 소유하는 항목:

- 문서 버전과 안정적인 객체 ID.
- 큐브·구·원기둥·평면·마네킹·실제 바닥 객체.
- 각 객체의 이름, 종류, 위치, 회전, 양수 크기, 색상, 표시 여부.
- `OutputCamera { position, target, focalLengthMm, rollDeg }`.
- 화면비, 출력 크기와 출력 모드에 필요한 설정.
- 조명 프리셋과 환경/키/필/림, 배경, 노출, 그림자에 필요한 직렬화 값.
- 선택적 피사체·카메라 모션 가이드 기록과 최대 2,000자 장면 메모.

문서 변경 중 히스토리에 들어가는 작업:

- 추가, 삭제, 복제.
- 확정된 변형 한 건.
- 이름, 색상, 표시 여부 변경.
- 명시적으로 확정된 카메라 변경.
- 조명, 배경, 화면비, 출력 설정, 모션 메타데이터 변경.

### 3.2 일시적 편집 상태

다음은 사용자 세션 동안만 필요하며 장면 JSON에 저장하지 않는다.

- 선택·호버 객체, 활성 변형 모드.
- 패널 열림 상태와 개별 가이드 표시 상태.
- dirty 상태, 상태 메시지와 오류 배너.
- `EditorNavigation`의 orbit/pan 중간 상태.
- 진행 중인 변형 초안.
- 내보내기 busy/progress/error 상태.

연속 기즈모 드래그는 런타임 객체만 갱신하고 drag end에서 최종 변형을 한 번 문서에 확정한다. 카메라 orbit/pan도 control end 또는 이름 있는 명시적 카메라 작업에서만 문서에 확정한다.

### 3.3 Three.js와 브라우저 런타임 객체

다음은 렌더러가 문서에서 재구성하거나 React ref로만 보유하며 절대 직렬화하지 않는다.

- `THREE.Object3D`, `Mesh`, `Group`, `PerspectiveCamera`.
- renderer, scene, material, geometry, texture, light, shadow map.
- `WebGLRenderTarget`과 픽셀 버퍼.
- OrbitControls/TransformControls 인스턴스.
- DOM 노드, Canvas 컨텍스트, `Blob`, 함수, 구독과 이벤트 핸들러.

문서 → 렌더러 방향의 파생을 기본으로 하며 런타임 객체를 Zustand 문서 안에 넣어 두 표현이 서로 어긋나는 구조를 만들지 않는다.

## 4. Zod 문서 경계

Zod는 버전이 있는 `SceneDocument`의 단일 입구다.

1. 기본 장면 팩터리는 스키마를 만족하는 JSON-safe 문서를 만든다.
2. localStorage 복원과 파일 JSON 가져오기는 문자열 파싱 후 전체 Zod 검증을 끝낸다.
3. 지원하지 않는 버전, 알 수 없는 필수 구조, 유효하지 않은 숫자·크기·ID가 있으면 실패한다.
4. 검증 성공 전에는 현재 장면을 교체하거나 유효 자동 저장 슬롯에 쓰지 않는다.
5. 실패 시 현재 장면과 이전 유효 자동 저장을 모두 보존하고 사용자가 조치할 수 있는 한국어 오류를 표시한다.
6. 향후 마이그레이션은 버전 경계에서만 수행한다. 서로 다른 문서 타입이나 부분 검증 경로를 만들지 않는다.

문서 타입을 별도 인터페이스로 중복 선언하지 않는다. 보조·일시 타입만 별도 타입 파일에 둔다.

## 5. 카메라 계약

### 5.1 OutputCamera

- OutputCamera는 문서 소유이며 최종 프레이밍의 유일한 진실의 원천이다.
- 저장 필드: `position`, `target`, `focalLengthMm`, `rollDeg`.
- MVP의 `filmGaugeMm`는 `36`으로 고정한 상수다.
- 렌즈는 `PerspectiveCamera.setFocalLength()`에 `18`, `24`, `35`, `50`, `85mm` 중 하나를 적용한다. 화면비별 추정 FOV 상수를 저장하지 않는다.
- 카메라 aspect는 언제나 활성 출력 aspect와 같다.

### 5.2 EditorNavigation

- orbit/pan의 진행 상태는 transient `EditorNavigation`이다.
- 움직이는 동안 문서와 히스토리를 프레임마다 갱신하지 않는다.
- control end, 샷 프리셋, 선택 항목 프레임 맞추기, 선택 항목 바라보기 같은 명시적 경계에서만 OutputCamera에 확정한다.
- 출력은 미확정 EditorNavigation을 읽지 않고 저장된 OutputCamera로 런타임 카메라를 새로 구성한다.

### 5.3 프리뷰와 출력 구도 동일성

- 뷰포트 크기와 출력 aspect로 contain 방식 레터박스 사각형을 계산한다.
- 레터박스 바깥은 마스크하고 안쪽만 카메라 프레임으로 보여준다.
- 레터박스 안쪽과 PNG는 같은 OutputCamera, aspect, scene layer, 색상 설정을 사용한다.
- 브라우저 리사이즈와 `devicePixelRatio` 변화는 표시 크기만 바꾸며 PNG의 크롭과 구도를 바꾸지 않는다.
- 비율 불일치는 이미지를 늘이는 방식으로 해결하지 않는다.

## 6. 렌더 레이어 계약

Three.js 레이어 ID는 MVP 전체에서 상수로 고정한다.

| 레이어 | 소유 콘텐츠 | 프리뷰 | 깨끗한 출력 | 참조 출력 |
|---|---|---:|---:|---:|
| `0` | 실제 바닥, 마네킹, 프리미티브, 배경에 대응하는 장면 콘텐츠 | 예 | 예 | 예 |
| `1` | 그리드, 축, 선택선, 변형 기즈모, 피사체 방향 보조축 등 편집 전용 도우미 | 예 | 아니오 | 아니오 |
| `2` | 선택적 피사체·카메라 모션 화살표와 참조 주석 | 선택 | 아니오 | 예 |

3분할선, 중앙 십자선, 5% 액션 안전 영역, 10% 타이틀 안전 영역은 DOM 오버레이다. 깨끗한 출력에는 포함하지 않는다. 참조 출력에서는 같은 퍼센트 좌표를 2D 출력 캔버스에 별도로 합성한다. 레이어 1은 어떤 출력 모드에도 들어가지 않는다.

깨끗한 출력과 참조 출력은 레이어 마스크와 합성 정책이 분리된 테스트 가능한 경로다.

## 7. 색상과 조명 계약

- 화면 프리뷰와 PNG 출력은 모두 sRGB 출력 색 공간을 사용한다.
- 배경, 노출, 톤 매핑 등 프레임 색에 영향을 주는 렌더러 상태는 프리뷰와 출력에서 같은 정책을 적용한다.
- 조명 모델은 환경 강도와 키/필/림의 강도·색·방향, 배경색, 노출, 그림자 설정으로 제한한다.
- 성능을 위해 그림자를 만드는 키 라이트는 최대 하나, 그림자 맵은 최대 `1024×1024`다.
- 중립 스튜디오, 주광, 일몰, 야간, 시네마틱 역광은 위 직렬화 값의 프리셋이며 개별 Three.js Light 객체를 문서에 저장하지 않는다.

## 8. 정확한 PNG 출력 경로

PNG는 편집 캔버스의 스크린샷이나 `toDataURL()`을 기본 경로로 사용하지 않는다.

1. 선택한 출력 너비·높이를 검증한다. 각 축은 `64..4096px`, 활성 화면비에 잠기며 비율 불일치는 거부한다.
2. 저장된 SceneDocument에서 OutputCamera를 재구성하고 출력 aspect와 `filmGauge=36mm`를 적용한다.
3. 정확한 픽셀 크기의 오프스크린 `WebGLRenderTarget`을 만들고 출력 `pixelRatio=1`로 렌더링한다.
4. 깨끗한 출력은 레이어 0만, 참조 출력은 레이어 0+2만 렌더링한다.
5. 렌더 타깃의 픽셀을 읽고 WebGL 좌표계에 맞게 행을 수직 반전한다.
6. 임시 2D Canvas에 픽셀을 쓰고, 참조 모드라면 퍼센트 기반 DOM 가이드를 같은 좌표로 합성한다.
7. `canvas.toBlob('image/png')`으로 인코딩하고 안전한 파일 이름으로 브라우저 다운로드를 시작한다.
8. 성공과 실패 모두 `try/finally`에서 이전 render target, viewport, 레이어, 색상 관련 상태를 복구하고 임시 GPU/Canvas 자원을 해제한다.

출력 크기는 브라우저 CSS 크기나 DPR에서 계산하지 않는다. `1280×720`, `1920×1080`, `1080×1920`, `1080×1080`, `1920×804`와 유효 사용자 지정 크기는 생성된 PNG 헤더를 디코딩해 검증한다.

## 9. 로컬 영속성

- MVP 장면은 프리미티브와 원시값만 포함하므로 이름공간이 있는 localStorage 키를 사용한다.
- 디바운스 자동 저장과 명시적 로컬 저장을 제공한다.
- `QuotaExceededError`는 장면을 잃지 않고 한국어 조치 안내로 표시한다.
- 파일 JSON 가져오기·내보내기를 별도 휴대 경로로 제공한다.
- 바이너리 에셋이 범위에 들어오기 전에는 IndexedDB나 서버 저장소를 추가하지 않는다.
- dirty 문서가 아직 저장되지 않았을 때만 `beforeunload` 경고를 사용한다.

## 10. 테스트 책임 분리

### Vitest가 책임지는 것

- 화면비·레터박스·카메라 거리 등 순수 수학.
- Zod 스키마, 버전 거부, JSON codec, 가져오기/자동 저장 보존 규칙.
- 문서/store 전이, 히스토리 allowlist와 1회 변형 확정.
- 프리셋 적용, 출력 크기·파일 이름·레이어 마스크 정책.
- WebGL이 필요 없는 DOM 전용 컨트롤과 접근성 상태.
- 출력 도중 예외가 날 때 상태 복구와 자원 해제를 검증할 수 있는 격리된 헬퍼.

Vitest/jsdom에서 R3F Canvas를 과도하게 mock해 실제 WebGL 렌더, raycast, 카메라 프레이밍이 동작한다고 주장하지 않는다.

### Playwright가 책임지는 것

- 실제 Chromium의 WebGL 가용성과 Canvas 시작.
- 메시 클릭/raycast, 그룹 마네킹 루트 선택, 가시성.
- TransformControls와 OrbitControls 상호작용.
- 가로·세로 레터박스, 렌즈와 카메라 프레이밍, 리사이즈 불변성.
- 실제 PNG 다운로드, 시그니처, 픽셀 크기, clean/reference 픽셀 차이.
- 리사이즈 전후 정적 장면의 pixelmatch 임계값.
- 저장/복원과 손상 JSON 실패를 포함한 3분 골든패스.

헤드리스 환경에서 WebGL이 없으면 테스트를 조용히 건너뛰지 않고 환경 진단과 함께 실패한다. 개발 서버뿐 아니라 production preview에서도 완전한 흐름을 검증한다.

## 11. 오류와 복구 경계

- WebGL 미지원 또는 context loss 시 직렬화 문서를 보존하고 복구 가능한 안내를 표시한다.
- 파일 파싱, 저장, 렌더, 인코딩, 다운로드 오류는 장면 문서를 변경하지 않는다.
- 내보내기 실패는 임시 렌더 상태를 반드시 복구한다.
- 선택 대상이 없는 카메라 명령은 무동작이며 상태 표시줄로 이유를 알린다.
- 지원 화면보다 작은 뷰포트에서는 깨진 편집기 대신 데스크톱 필요 안내를 표시한다.

## 12. MVP에서 만들지 않는 경계

서버/API, 인증, 클라우드 동기화, Electron/Tauri, 임의 외부 메시·텍스처, 모델링·리깅·타임라인, 물리·후처리·레이 트레이싱, AI 생성 연동, 모바일 터치 편집은 이 아키텍처에 포함하지 않는다. 이 기능을 위해 미리 플러그인 계층, 백엔드 인터페이스, 번역 프레임워크를 만들지 않는다.
