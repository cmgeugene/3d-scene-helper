# S19 — Keyframe refinement

## 결과

완료된 키프레임을 고충실도 입력으로 다시 첨부해 한 번의 보정 생성을 수행하는 흐름을 구현했다.

- 기본 생성: 3D 레이아웃 1장 + 레퍼런스 최대 4장
- 보정 생성: 선택한 원본 키프레임 1장 + 현재 3D 레이아웃 1장 + 레퍼런스 최대 3장
- 결과 카드의 `이 결과를 기반으로 보정` 버튼으로 진입
- 보정 모드에서는 레퍼런스 선택 한도와 전체 이미지 입력 카운터가 동적으로 변경
- 보정 요청은 `parentGenerationId`, `feedback`, `generationMode: edit`로 기록
- 원본 키프레임은 첫 번째, 현재 3D 캡처는 두 번째, 역할별 레퍼런스는 세 번째 이후 입력으로 전달

보정 모드에서 여러 번 생성해도 `refinementSource`는 처음 선택한 키프레임으로 유지된다. 따라서 직전 파생 이미지를 연쇄 편집하지 않고 같은 원본에서 형제 결과를 만들 수 있다.

## 서버 무결성 규칙

- `fresh` 요청은 부모 generation을 지정할 수 없다.
- `edit` 요청에는 완료된 결과를 가진 부모 generation이 필요하다.
- `fresh`의 reference ID는 최대 4개다.
- 원본 키프레임과 레이아웃을 모두 포함하는 `edit`의 reference ID는 최대 3개다.
- generation attachment 기록에는 `sourceGeneration`, `layout`, `reference` 역할과 순서를 저장한다.

## 수동 확인

1. Companion과 앱을 다시 시작하고 기본 이미지를 한 장 생성한다.
2. 완료 결과 아래에서 `이 결과를 기반으로 보정`을 누른다.
3. 레퍼런스 카운터가 최대 3장으로 바뀌는지 확인한다. 기존에 4장이 선택되어 있다면 한 장을 해제해야 한다.
4. `전봇대가 가리는 비율만 조금 줄여줘`처럼 변경 범위가 좁은 피드백을 입력하고 `보정 생성`을 누른다.
5. `generations.json`의 새 기록에서 `generationMode: edit`, 부모 ID, 피드백, v2와 `sourceGeneration` attachment를 확인한다.
6. 같은 보정 모드에서 다시 생성했을 때 새 결과도 처음 선택한 원본을 부모로 사용하는지 확인한다.
