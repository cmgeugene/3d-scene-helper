### Code-quality 리뷰 Important 수정 사이클

- 기존 구현에서 dev server가 `4173`에 떠 있으면 preview 시작이 실패해도 Playwright가 그 dev server를 재사용해 `test:e2e:preview`가 종료 코드 `0`이 되는 false positive를 재현했다.
- 수정: cross-platform Node port preflight, 일반 E2E의 `reuseExistingServer: false`, external-server 전용 실행에서 `webServer` 비활성화, production preview 응답 marker 검증을 추가했다. 같은 stale dev server 회귀 검증은 종료 코드 `1`과 명시적 재사용 거부 문구를 반환했고 서버를 정리한 뒤 포트가 비어 있음을 확인했다.

## 결정과 범위 준수

- 최소 앱 셸은 제품명, 현재 단계 설명, WebGL 상태만 제공한다.
- WebGL probe는 임시 canvas에서 `webgl2` 다음 `webgl`을 시도하고 `WEBGL_lose_context`가 있으면 즉시 해제한다.
- jsdom은 fallback을 결정적으로 검증하고, available 경로는 테스트용 컨텍스트로 별도 검증한다.
- R3F Canvas, Zustand store, Zod scene schema, Three.js scene 객체는 아직 만들지 않았다. 설치만 S01 계획대로 완료했다.
- backend, 저장, 내보내기, 3D 편집, i18n 계층을 추가하지 않았다.

## 알려진 제한

- 현재 화면은 실행 환경 점검용이며 실제 장면이나 편집 기능이 없다.
- Playwright는 재현성을 위해 SwiftShader를 사용한다. 일반 브라우저의 `npm run dev`/`preview`는 브라우저 기본 하드웨어 WebGL 정책을 따른다.
- WebGL unavailable/context-loss 상태에서 scene data를 보존하는 완전한 오류 경계는 scene document가 생긴 뒤 S11에서 구현한다. S01은 명시적 fallback 문구만 제공한다.
