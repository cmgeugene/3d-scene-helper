## 구현한 계약

### Preset과 document mutation 경계

- 5개 preset은 compact JSON-safe environment/key/fill/rim, exposure, shadow 및 background 값만 가진다.
- `applyLightingPreset(document, presetId)`는 deterministic pure document transformation이며 unknown ID를 `RangeError`로 거부한다.
- preset 적용과 reset은 lighting/background만 바꾸고 objects, output camera, guides, output 및 metadata 값을 보존한다.
- store action 하나가 document change 한 번을 만든다.
- reset은 현재 preset ID의 canonical lighting/background로 복귀한다.
- 직접 lighting/background 편집은 preset ID를 유지하므로 같은 preset baseline으로 reset할 수 있다.

### Actual Three/R3F lighting rig

- environment는 one ambient light, key/fill/rim은 three directional lights로 materialize한다.
- 각 directional light position은 document direction에 stable meter scale을 적용한다.
- key만 `castShadow`를 사용하며 fill/rim은 항상 false다.
- shadow map width/height는 document 값과 관계없이 `MAX_SHADOW_MAP_SIZE=1024`를 넘지 않는다.
- bounded orthographic shadow camera, bias와 renderer-supported PCF radius를 사용한다.
- document exposure는 actual `WebGLRenderer.toneMappingExposure`에 적용되고 render invalidation을 요청한다.
- runtime light/renderer/shadow object는 component ref에만 존재하며 Zustand/document에 들어가지 않는다.

### Inspector controls와 numeric editing

- 조명 panel은 5개 preset을 선택하는 labelled select를 제공한다.
- exposure, background color, key direction X/Y/Z, shadow toggle과 reset button을 제공한다.
- exposure와 key direction은 local string draft를 사용해 실제 순차 keyboard input의 intermediate state를 보존한다.
- Enter 또는 blur가 explicit numeric commit boundary다.
- Escape는 draft를 버리고 committed value를 복원한다.
- exposure는 0.1–3, key direction axis는 -3–3 범위를 commit path에서 강제한다.
- preset/reset과 외부 canonical update는 focus를 벗어난 field에 즉시 반영된다.

### Runtime diagnostics와 production 격리

- DEV/Vite `e2e` mode에서만 preset ID, exposure, environment intensity, key/fill/rim color/intensity/position/castShadow, shadow map/radius를 plain JSON canvas attribute로 게시한다.
- diagnostic은 actual runtime Three object에서 읽되 Three instance 자체를 직렬화하지 않는다.
- `scripts/assert-production-bridge-absent.mjs`가 일반 production bundle의 `runtimeLighting` marker를 금지한다.
- preview E2E 뒤 일반 production build를 다시 생성하고 diagnostic exclusion을 재확인했다.
